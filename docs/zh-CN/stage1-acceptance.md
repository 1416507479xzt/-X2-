# 环节一：迎宾问候与健康问询验收

注意：本页保留旧 `auto/rules` 模式的验收说明，其中固定开场和固定表现不适用于
当前默认 `model` 模式。新模式的启动、模型统一决策及AimDK接入边界请见
[模型统一决策与真机表现接入](model-presentation.md)。

本次只优化环节一。普通 `python agent.py` 仍运行原通用示例；必须加 `--competition-mode`。

## 启动

保持 Windows 便携版模拟器运行。旧 Agent 终端按 Ctrl+C 退出，然后执行：

```powershell
cd "D:\zhejiangshuzhidasai\Unity-Agent-Playground-main\Unity-Agent-Playground-main\example\x2_agent"
python agent.py --competition-mode
```

无需更换已配置的 API Key，无需重装 Unity 或改用 C++。同一时刻只运行一个语音 Agent。

首次连接保持安静，终端提示等待语音唤醒。先单独说“灵犀”“你好灵犀”或“灵犀灵犀”，识别到唤醒词后才发起问候，首包语音准备好时发送挥手与开心表情。唤醒名通过 pypinyin 在本机转换为无声调拼音，接受 `ling xi`，并兼容实际日志中的 `lin xi` 前后鼻音混淆；无需枚举所有汉字写法，例如“灵溪”“凌曦”“林夕”“琳熙”均可识别。支持同一段录音连续呼叫（最多六次）、问候前后缀和 X2 后缀。整句必须是呼叫形式，“林夕是谁”“不要叫灵犀”等不会唤醒。开场统一使用“您好”，不假定来访者姓名；旧命令传入的 `--elder-name` 不用于称呼。唤醒前其他语音不进入聊天、不记为健康状态；每轮仍正常结束以继续监听。

唤醒后可以连续对话，不需要每句话都说唤醒词；再次叫“灵犀”只回答“我在，您说”，保留当前问询进度。若开场合成失败，可以重新说唤醒词重试。机器人说完再回答；当前模拟器是半双工交互，不代表已经支持说话中打断。重连不会重播开场，若要重新完整演示，退出并重新启动 Agent。

唤醒通过现有云端语音识别结果判断，唤醒前识别仍会联网并可能计费，不是本地离线关键词检测。暂按单独唤醒、再回答问询的方式演示。

拼音匹配可容忍同音字、声调差异以及上述 lin/ling 混淆，但无法恢复空识别结果或任意错误转写，也无法判断呼叫来自现场人员还是背景录音。新增依赖后，在运行 Agent 的 Python 环境执行 `python -m pip install -r requirements.txt`。拼音转换 API 见 [pypinyin 官方文档](https://pypinyin.readthedocs.io/zh-cn/v0.52.0/api.html)。

## 对话验收

以下检查“理解与行为”，不要求每次逐字相同。各条可从重新启动、语音唤醒后的问候开始，以免前一条的对话阶段影响下一条。

| 场景 | 老人说法 | 应观察到的结果 |
| --- | --- | --- |
| 语音唤醒 | 刚启动时先不说话，再单独说“你好灵犀” | 启动时不问候、不挥手；唤醒后才问候、挥手、显示表情 |
| 疲惫 | “今天有点疲惫” → “昨晚没睡好” | 关怀回应，追问睡眠；第二轮结合回答自然结束，不说“呜，有点难过” |
| 情绪 | “心情不太好” → “有点想孩子” | 先共情，再回应想念家人，不机械地表示机器人自己难过 |
| 腰部不适 | “腰有点酸” → “好几天了” | 询问持续时间，建议让医护了解情况；不诊断、不指导治疗 |
| 状态良好 | “今天还行” → “想听音乐” | 正向回应并记住兴趣，不把表达兴趣等同于已经播放音乐 |
| 否定 | “我不是心情不好，只是没睡够” | 不归类为心情低落，不擅自推断睡眠发生在昨晚 |
| 改口 | “有点累” → “不是，我其实心情不好” | 更新理解，回应新状态，不继续机械回答睡眠问题 |
| 拒绝 | “不想说” | 尊重选择并结束，不再追问隐私 |
| 记忆 | 完成疲惫问询后问“知道我刚才说了些什么吗？” | 复述本人已经说出的状态及细节，不编造原因 |
| 问询中回忆 | “有点累”后问“我刚才说什么了？” | 回忆已确认信息，不把这句话当作睡眠答案 |
| 换话题 | “有点累”后问“今天该吃药了吗？” | 转交当前请求，不用“谢谢您告诉我，注意休息”吞掉问题；因未接入用药计划，不得编造服药时间 |
| 陌生说法 | “我像电量只剩一格似的” | auto 模式尝试语义理解；无法可靠判断时澄清，不胡乱记录状态 |
| 他人与过去 | “我老伴今天有点累”或“昨天累，今天很好” | 不直接凭“累”记录为本人当前疲惫；尝试语义判断，失败时保守澄清 |
| 纠正细节 | 已提到没睡好，再说“我刚才说错了，其实昨晚睡得很好” | 更新睡眠记录，不重复开场，也不据此否认之前明确说过的疲惫 |
| 未听清 | “嗯”或模糊回答 | 有限次数澄清，不无限循环，也不伪造健康状态 |

## 语音、表情和动作

- 开场只发一次挥手；普通健康交流以语音和表情为主，不额外走动或连续挥手。
- 表情在首包语音前下发，持续时间按话语长度估计并限制上限；实际同步效果仍需在模拟器观察。
- 工具请求已发送不代表动作已执行完成；以模拟器实际展示和技能状态为准。
- 没有动作控制权时仍可对话，但不会擅自执行表情或动作。若缺少展示，请检查控制台是否接管。
- 语音失败或轮次被取消，问询状态会回滚以便重试；不把没成功下发的回答算作已经完成的问询。

## 语义模式与延迟

默认 auto 在本地无法可靠判断的问询表达上，使用现有方舟模型提取受限结构化结果，不把模型生成的 JSON 朗读出来。判断时间上限约 1.5 秒，流清理另有短超时；第一轮错误、超时或无效结果退回本地澄清。第二轮自由表达若无法由规则承接，则携带上一问题、已确认状态及聊天历史进入普通对话生成，不直接宣称没听清并结束。该路径会增加模型调用和延迟，实际语言质量仍需联网试听。

短回答按当前问题解释：问睡眠后的“还行”指睡眠尚可，保留此前的疲惫状态；问整体状态后的“还行”才指整体尚可。已明确想继续聊天时，接一个简短问题，不在同一句后追加告别语。可验收“今天有点累→还行”“心情不好→跟邻居拌了几句嘴”“还行→想聊天”。

需要对照本地规则路径时：

```powershell
python agent.py --competition-mode --health-semantic rules
```

这只关闭语义分类器，普通聊天、语音识别和语音合成仍会联网。未进行现场云服务和扬声器验收，不能把离线单元测试通过等同于语音效果或比赛得分。

可选地记录指标：

```powershell
python agent.py --competition-mode --metrics-file stage1-metrics.json
```

Ctrl+C 正常退出时生成统计。`health_response_ms` 是问询决策耗时，`health_semantic_ms` 是语义分类耗时，`commit_to_first_audio_ms` 从网关提交录音开始到合成首包，不包含完整的静音判尾及扬声器起播，不能直接当作比赛要求的端到端延迟。

实际验收应记录“老人最后一个有效语音 → 机器人第一个有效语音”，多轮测试常见和陌生说法，并观察慢的一组情况。

## 边界

- 本轮仅保存进程内记忆，不写入长期个人健康档案；退出程序后清空。
- 身体不适原话按部位独立保存在本次会话中，供本地回顾和大模型回答共同使用，不随最近五轮聊天窗口丢弃。每个部位保留最近一次明确描述，新的腰部描述不会覆盖脖子描述；“脖子不疼了”等明确更正仅更新对应部位。只保留可明确识别的自述，不把提问、假设或家人的症状当作本人症状；目前不是任意自然语言事实的完整记忆系统。
- 记忆验收：说“我现在感觉脖子有点疼”，随后说“我感觉腰有点酸”；聊超过五轮其他内容后，问“我和你说过我身体哪里不舒服”“我的脖子呢”，应仍能回顾两处不适或按指定部位回答。再说“脖子已经不疼了”，回顾应体现更正，并保留腰部记录。
- 环节二用药知识与提醒计划、社区报名等服务未由本轮实现。话题切换只解决请求不被吞掉，不代表已完成这些服务。
- 保留 Python 业务与网关连接分层，没有实现或验证完整的 AimDK 真机适配器，不宣称已达到真机零修改验收。
- 当前采用语音唤醒后问候；评分中主动与触发问候的认定须按现场规则确认。
