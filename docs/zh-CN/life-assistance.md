# 第二环节：用药咨询与健康提醒

与第一环节共用程序、对话记忆及语音/表情/动作通道，资料模块独立。
在 model 模式下，服务请求和后续澄清由大模型理解，使用 other/continue，
不要求先结束健康问询。唤醒机制不变，先唤醒再提出请求。

## 启动

在 example/x2_agent 目录中运行：

```powershell
python agent.py --competition-mode --health-semantic model --presentation-backend unity
```

默认资料为 `data/life_assistance.json`，每轮重新读取，修改后无需重启。
可用 `--service-data "绝对路径"` 指定另一份资料；文件错误时拒绝使用，不静默丢弃问题行。
最多20份药品资料、40条提醒，文件不超过64KiB。资料会随对话发送给配置的大模型服务，
请勿放入无授权的真实健康记录。该模块不依赖Windows路径或机器人SDK。

## 药品资料（首批，不是完整常用药库）

2026-10-23新增八种药物的NHS科普摘要（data/medicine-education.json），仅解释用途，不能替代中国产品说明书。
medicines收录宁夏康亚氨氯地平5mg和成都恒瑞阿托伐他汀10mg的厂家资料摘要，来源链接、核对日期随记录保存。
康亚页面标为简短处方资料，不是完整说明书；所有摘要均不是完整禁忌、相互作用或个人用药建议。
仍缺少其他产品的可用剂量资料，不能声称已覆盖全部老年常用药。
每项字段：name 完整名称、strength 规格、form 剂型、source 可核对来源、
usage 说明书用法用量原意、precautions 注意事项、reviewed 人工核对布尔值。
只有 reviewed=true 且必填身份和来源字段完整的资料进入模型；这个标记不是自动医学审核。
usage 为空必须承认缺少剂量，不能推测。不要把一般说明书当作个人医嘱。
模型仍可能生成错误内容；上线前必须逐项核对回答，没有模型外的医疗正确性保证。
程序在当前完整身份，或最近连续纯身份短答中核对完整药名、规格、剂型和厂家，才提供usage/missed_dose字段。
只合并最多4条连续的用户原话，不把机器人回答作为身份事实；自由叙述、改口或换话题打断合并。
否认或不确定表达不解锁剂量。不能可靠匹配时宁可重新核对，不能猜测ASR误识别的药名。
例如：宁夏康亚药业的苯磺酸氨氯地平片，5毫克普通片，我想了解资料中的吃法。
新增模板为data/medicine-template.json，不会自动加载；其中别名、适用人群、禁忌、相互作用、漏服和服药方式可独立维护。
重复同一产品身份的记录会报资料不可用，避免模型遇到冲突用量自行选择。

## 用量与追问输出校验（2026-10-23）

纯身份短答缺信息时，由missing_identity_fields确定下一项，回答必须含针对性问句。
模型可以输出[[MEDICINE_QUESTION]]，程序在播报前填入明确问句。
模型选择引用用量时，可输出[[MEDICINE_USAGE]]，程序完整填入已核对的usage及首条注意事项，
避免模型漏掉特殊人群、频次、上限和个人医嘱边界。标记不进入语音或对话记忆。
仍自行写数值时，输出校验要求保留完整原段及首条注意事项；不接受增加其他片数或剂量。
展开后重新校验180字限制，超限不截断用量。失败最多修正一次，仍不合格则只提示核对，不播报剂量或动作。
自然语言和表情动作仍由大模型决定；关键药品事实使用受约束引用，不宣称纯模型自由生成。

局限：数值识别是有限格式的保守校验，不是完整自然语言医疗审核；无法证明未列出的禁忌不存在，
也不保证底层摘要覆盖所有适应症和个人情况。本轮未扩充药品种类，不代表常用药库已经齐全。
缺说明书的产品仍需如实说明，正式使用须医生或药师审查，并测试真实语音误识别场景。

## 提醒资料

### 自然播报调整

提醒标题中的“（演示）”只保留在后台，播报时去除；不把完成状态作为括号字段逐项读出。
demo仍为true，未修改为真实医嘱或医院预约。用药相关回答保留“预设时间、实际按医嘱”的边界。
新增[[REMINDER_REMAINING]]，专门回答今天还有什么，仅使用remaining_today；全天回顾仍用[[REMINDER_TODAY]]。
下午所有事项都已过点时，不再重读上午清单；下一项可以是明天，但不会把明天当今天。
口语时间与事项仍由程序生成，模型选择查询类型及表情动作。模型选错类型仍可能导致答非所问，需继续验收。

默认 demo=true，两项虚构演示安排，不包含真实用药计划。回答必须说明是演示安排。
每条包含唯一 id、date（YYYY-MM-DD 或 daily）、time（HH:MM）、
kind（water/appointment/medication/other）、title、可选 detail。
使用中国时间 UTC+08:00；程序计算今日安排及下一项，包含下一日的每日重复事项。
时间已过只表示完成情况未知，不代表漏服或完成。
`remind_before_minutes`默认为30，可设0至1440的整数，表示对话时哪些未来事项属于“近期可补充提醒”，
不是后台定时器。当前分钟到点使用due_now，之后使用passed_unknown；程序给出今天剩余事项、
下一项（可能在明天）、准确中文时间、剩余分钟数、日期独立的occurrence_id，避免混淆每日重复事项。
模型可用[[REMINDER_NEXT]]或[[REMINDER_TODAY]]引用程序计算的时间内容，标记在播报前展开，
并仍遵守字数与表达校验。今日超过三项会说明剩余数量，不声称全部播报完。
用户自述完成只留在本段对话记忆，不持久化修改配置，不是系统已验证服药。
最新实现：提醒请求使用独立reminder意图，模型从“今日/下一项/服药时间/不支持修改”四种查询结果中选择，
reply必须为对应标记；程序生成事实段并重新校验。表情动作由模型选择，提醒事实段不是模型自由改写。
发现无标记的reminder回答或明显虚假的修改承诺时最多修正一次，失败给明确核对提示，不直接播报错误安排。
模型把意图分错时仍可能绕过部分检查，需要持续测试；这不是所有自然语言错误的完备检测。
真实模式需自行提供已核对安排并设 demo=false，目前单份资料，不支持多人身份识别。

本版实现查询时主动补充近期事项，不实现后台定时播报、不打断老人讲话；
也不支持语音创建、修改或完成事项，机器人不能声称已保存。
这不是环节二第三类“依据用药史每日定时提醒”的实现。

健康提醒纯文本测试：`python scripts/check_care_dialogue_live.py --live --scenario reminders`。
最多12次模型调用，使用固定的虚构测试时钟2026-10-23 09:45（北京时间），不改变系统时间、实际配置或启动定时器。
覆盖今日安排、下一项准确时间、简短确认、无用药安排和不支持语音修改的边界。

## 验收

2026-10-23修复：健康追问中“回应，问题？”与“回应。问题？”都允许正常交付。
没有独立陈述句只记录health_followup_single_sentence质量提示，不触发修正或通用“抱歉”兜底。
这不保证只有提问的回答足够贴心；质量要求仍由提示词指导。JSON、问询轮数及药品安全校验保留。
纯文本实测命令：`python scripts/check_care_dialogue_live.py --live --scenario healthy_transition`，
会调用付费API（最多10次），不连接模拟器。覆盖“今天还好→今天挺好的→降压药怎么吃→具体药名”。

先正常完成第一环节，再说“降压药怎么吃”，应澄清完整名称和规格；
即使说出具体药名，没有资料时也不能报剂量。
再问“今天有什么安排”“下一项是什么”，应按资料和当前时间回答，并明确演示性质。
问“你还记得我哪里不舒服吗”，应保留第一环节的原话。
直接唤醒后询问生活服务也可进入，不需先走完健康问询。
资料不足时功能可运行，但尚不具备正式药品演示的内容条件。

## 当前实测边界（2026-10-22）

真实模型纯文本测试可完成药名澄清、两条演示安排查询、下一日10:00提醒查询及回顾脖子不适。
尚未进行本次Unity语音端到端或真机测试。模型仍有把资料外的颈部活动建议加入回答、
以及承诺凭药名即可核对说明书的倾向；提示约束不等于硬性安全保证。
正式用药演示前须补充资料并做人工逐句验收，不能直接用于真实长者的用药决策。
